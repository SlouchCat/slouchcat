# Which server test packages CI runs in which parallel job (scripts/testgroups.sh, ADR 0013).
#
# Format: "<group> <package below server/>". Everything this file does not name forms the group
# "rest", which scripts/testgroups.sh computes from `go list ./...` -- so a new package is tested
# from its first day without anyone having to remember this file. The workflow does not list the
# groups either; it asks `scripts/testgroups.sh --matrix` and builds its matrix from the answer, so
# a group added here gets a job by itself.
#
# `scripts/testgroups.sh --check` runs in `task server:lint` and fails when a name here is no
# longer a package.
#
# Locally this file does nothing: `task server:test` and `task ci` run every package at once.
#
# How the groups are cut. The weights are the per-package elapsed times of one local
# `taskset -c 0-3 go test -race -count=1 -json ./...` -- the four-core model of the runner, which
# matched the serial CI run 40207488836 when the groups were first cut. Not CPU time, but close
# enough to it while all four cores are busy. Measured on 3 November 2026, after the test helpers
# moved to the template database of internal/store/storetest (whole run 1078 s, before 2146 s on
# the same machine; the machine was shared, so the absolute numbers are high, the proportions
# hold):
#
#   store 803.6  api 483.7  library 140.1  admin 133.1  playback 116.7  notify 112.5
#   offline 99.7  transcode 98.6  metadata 85.9  visibility 85.5  discover 70.3
#   cmd/slouchcat 53.2  jobs 31.0  auth 27.4  store/storetest 23.8  integrations 19.6
#   segments 19.5  everything else under 2 (18.5 together)
#
# Before the template database the order was admin 1253.5, api 1069.6, store 826.3, library
# 817.8, metadata 790.6, playback 488.7: nearly every test paid for all migrations under -race.
# internal/store still does, by design -- its tests are the migration, frozen-state, backup and
# restore tests that must run the real store.Open -- so it is now the floor on its own.
#
# Groups 1 and 2 are one package each because they are the two heavy ones. Groups 3, 4 and "rest"
# are bundles of 373 to 386 each, which also use the four cores better -- `go test -p 4` runs
# several package binaries at once, and a single serial package leaves three cores idle. metadata
# and playback sit in different groups; both were heavy before and are the first to grow again.
