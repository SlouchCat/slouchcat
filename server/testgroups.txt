# Which server test packages CI runs in which parallel job (scripts/testgroups.sh, ADR 0013).
#
# Format: "<group> <package below server/>". Everything this file does not name forms the group
# "rest", which scripts/testgroups.sh computes from `go list ./...` -- so a new package is tested
# from its first day without anyone having to remember this file. The workflow does not list the
# groups either; it asks `scripts/testgroups.sh --matrix` and builds its matrix from the answer, so
# a group added here gets a job by itself.
#
# `scripts/testgroups.sh --check` runs in `task server:lint` and fails when a name here is no
# longer a package.
#
# Locally this file does nothing: `task server:test` and `task ci` run every package at once.
#
# How the groups are cut. The weights are the per-package elapsed times of one local
# `taskset -c 4-7 go test -race -count=1 -json ./...` -- the four-core model of the runner, which
# matched the serial CI run 40207488836 when the groups were first cut. Not CPU time, but close
# enough to it while all four cores are busy. Measured on 4 November 2026, after the test helpers
# moved to the template database of internal/store/storetest and the store and playback tests
# went parallel (whole run 671 s; 2146 s before the template database, 1078 s with it but still
# serial; the machine was shared, so the absolute numbers are high, the proportions hold):
#
#   api 474.4  store 399.3  library 141.7  admin 126.1  transcode 115.4  notify 108.0
#   visibility 104.4  offline 100.0  metadata 83.4  playback 71.2  discover 71.2
#   cmd/slouchcat 48.7  jobs 32.1  auth 26.1  segments 24.0  store/storetest 19.0
#   integrations 17.5  everything else under 2 (18.5 together)
#
# api is the floor: one test, TestContractChildProfiles, takes 437 of its 474 and runs its
# subtests one after the other on a shared fixture, so no split of the package would help.
# store follows as the second group of its own. Its tests are the migration, frozen-state, backup
# and restore tests that must run the real store.Open, now in parallel.
#
# The other 1108 go into three bundles of 366 to 374 each (groups 3, 4 and "rest"), which also use
# the four cores better -- `go test -p 4` runs several package binaries at once. Fewer jobs would
# not be faster: two bundles of the remainder would be 554 each, above the api floor. metadata and
# playback sit in different groups; both were heavy before and are the first to grow again.
