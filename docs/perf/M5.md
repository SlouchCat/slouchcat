## 5. Start ohne Netz (C-1)

| Messung | Chromium | Firefox | Grenze |
|---|---|---|---|
| Echter Kaltstart ohne laufenden Server, dauerhaftes Browser-Profil (Langzeittest Tag 0, zwei Läufe) | 1334 ms, 1357 ms | 1446 ms, 1427 ms | < 3000 ms |
| Neuladen im Playwright-Flugmodus bei laufendem Service Worker (`setOffline`) | 76 ms; neue Tabs 88–141 ms | nicht in Playwright messbar (siehe unten) | < 3000 ms |
| Start mit einem Server, der nie antwortet (Sitzungsabfrage mit 2-s-Timeout; die Spec sperrt den Service Worker, die App-Hülle kommt vom Server) | 2375 ms | 2404 ms | < 3000 ms |

Firefox erfasst in Playwright mit `setOffline` die Anfragen des Service Workers nicht (die Sitzungsabfrage bekam im
«Flugmodus» 200); eine Sperre der API über eine Route lässt Firefox den Worker umgehen. Die Kaltstart-Specs laufen
deshalb nur in Chromium (Grund in `web/playwright.config.ts`). Der Langzeittest startet Firefox ohne laufenden Server,
also wirklich offline: Dort erscheint die Offline-Bibliothek in 1446 ms.

## 8. Beobachtungspunkte für den Betrieb (Server-Review K14)

- Eine `evicted`-Kopie, die das Gerät nie vollständig abholt (z. B. «nur WLAN» auf einem Gerät nur mit Mobilfunk),
  bereitet der Sync alle 7 Tage neu vor; das kostet je Woche einen Encode.
- `checkOfflineRevocations` ist öffentlich und ohne Ratenbegrenzung (höchstens 2000 IDs je Anfrage, indizierte
  Abfragen); bei Missbrauch nachrüsten.
